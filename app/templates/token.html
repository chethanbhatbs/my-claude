Where these numbers come from (and what leaves this machine)
One request: GET https://api.anthropic.com/api/oauth/usage, authorised with your Claude Code OAuth token read from the macOS keychain entry Claude Code-credentials — the same entry the claude CLI made and uses. The token is sent in the Authorization header and nothing else goes with it: no transcripts, no prompts, no filenames, no telemetry. It is held in memory for 10 minutes and never written to disk. This happens while this page is open (on load, every 60s, and on Refresh), and every 10 minutes in the background only if you turn on Notify me at 80% and 95%. Decline the keychain prompt and nothing breaks — the panel falls back to the copy Claude Code already cached in ~/.claude.json and says so, with the age of those numbers. Every other page in this app is computed from files on your disk with no network access.

Why does this differ from Claude Desktop?
  • Claude Desktop's "Total tokens" usually reflects context tokens (input + output), not the billable total.
  • Cache reads are billable (~10% price) but not shown as "new" tokens in Claude Desktop's headline. "Cache saved" is the difference vs paying full input price.
  • This aggregates only Claude Code transcripts on this machine.
